# id-copy-maker 功能测试用例集

需求来源：docs/requirements.md。本文是 id-copy-maker 的功能测试用例集：从使用者的角度出发，按业务场景写端到端用例。用例的写法、需求点记法、脚本与执行规矩见项目技能 `.thincoder/skills/test-case-design`、`test-script-gen`、`test-run`、`test-triage`。

## 1. 执行约定

### 1.1 执行方

| 记号 | 含义 |
|---|---|
| 自动 | Playwright 脚本在本机 Chrome 上以 file:// 打开 `index.html`，按用户操作走一遍并检查页面与导出文件；命令 `npm run test:e2e`（可在 `--` 后写触发原因），脚本在 `test/e2e/`。每次运行的截图、trace 与 HTML 报告存在 `test/e2e/runs/<时间>/`（不进版本库，只留最近 10 次），执行记录自动追加到 `docs/tests/run-log.md`。排查时单独重跑某个用例用 `npx playwright test <脚本文件> -g <用例名>`，证据写进 `test/e2e/runs/latest/`，不进执行记录。运行前提：Node 20 及以上、本机已装 Chrome，执行过 `npm install` |
| 桌面 | 电脑上的 Chrome、Edge、Safari 最新版，双击 `index.html` 打开（file://），由测试执行者手工操作 |
| 真机 | iOS Safari 16 及以上、Android Chrome 最近两个大版本，由产品所有者在自己的手机上执行 |

各场景的执行方写在场景开头。自动脚本的 M1 至 M8 按下表的尺寸、方向、元数据在运行时生成；HEIC 用带 HEIC 文件头的假数据。

### 1.2 测试素材

| 编号 | 素材 | 用途 |
|---|---|---|
| M1 | 身份证正面照片，清晰、端正，长边 2000 至 4000 像素 | 常规流程 |
| M2 | 身份证反面照片，同上 | 常规流程 |
| M3 | 横着拍的身份证照片（卡片在照片里转了 90°） | 旋转 |
| M4 | 小照片，比如 800×500 | 画质不足 |
| M5 | 手机拍的 12MP 照片（约 4000×3000）；另备一张长边超过 4000 的大图，比如 6000×4000 | 大图 |
| M6 | HEIC 格式的照片 | 错误提示 |
| M7 | 一个不是图片的文件，比如 .txt 或 .pdf | 错误提示 |
| M8 | 带 GPS 定位的手机原图（相册里能看到拍摄地点） | 隐私核对 |

素材用假证件或打码样张即可，不必用真证件。

### 1.3 通用检查

- 每个场景走完后看一眼页面：没有卡住、没有空白区块，五个区块的状态徽标与实际进度一致。
- 导出文件用系统自带的预览程序（访达预览、Windows 照片或 PDF 阅读器）打开查看。
- 需要量尺寸的场景，把 PDF 按「实际大小」或 100% 比例打印到 A4 纸上，用直尺量。

## 2. 场景用例

### S1 租房备案：双面复印件，导出 PDF 打印

目的：用户要交一份带「仅用于租房备案」水印的双面复印件。
执行方：自动（s01）；第 10 步打印后用尺子量为桌面手工，自动脚本按导出图边框像素换算毫米代替。需求点：§3-1 至 §3-6、§4-1、§4-2、§6-1、§6-3、§6-4、§6-6、§6-9、§7-1、§7-2、§7-3、§7-4、§7-5、§10-3。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 打开页面 | 顶部写着「所有处理都在本机完成，图片不会上传。」；五个区块按 1 正面、2 反面、3 水印、4 版面预览、5 导出与清除排列；正面、反面徽标为「未选图」；预览区写「尚未确认任何一面」；导出按钮不可点，旁边写明原因 |
| 2 | 在 1 正面点「选图」，选 M1 | 出现裁剪区和固定提示「歪的照片建议重拍或换一张正的图。」；裁剪框比例像身份证，初始是图里能放下的最大框并居中；徽标变为「裁剪中」 |
| 3 | 按住框内拖动，往图片外拖 | 框整体跟着移动，到图片边缘就停住，拖不出去 |
| 4 | 拖一个角点向内、向外 | 框按身份证比例整体放大缩小，形状不变，角不能单独拉变形 |
| 5 | 调到证件正好在框内，点「确认裁剪」 | 裁剪区收起，徽标「已确认」；预览出现 A4 纸，上半页有正面，带细黑边框 |
| 6 | 在 2 反面对 M2 做同样的操作 | 预览下半页出现反面；预览徽标「已生成（正反两面）」 |
| 7 | 3 水印保持默认开启，选「仅用于租房备案，复印无效 日期」 | 日期已填好今天；水印徽标显示完整水印文字，比如「已开启：仅用于租房备案，复印无效 2026年10月26日」；预览两张卡片上出现灰色斜排的水印 |
| 8 | 点「导出 PDF」 | 浏览器下载一个文件，名为「身份证复印件_当天日期.pdf」，比如 `身份证复印件_20261026.pdf`；导出区显示「已导出：文件名」 |
| 9 | 打开 PDF | 一页 A4 竖版；正面在上、反面在下，水平居中，两张之间约 3 厘米；每张有细边框；水印只在两张卡片上，斜着排，灰色半透明，每张卡上能看到 2 到 3 行以上；纸面空白处没有水印；看起来和预览一致 |
| 10 | 按实际大小打印到 A4，用尺子量 | 每张卡片 85.6×54mm，误差不超过 ±0.5mm；拿真证件比对，大小重合 |

### S2 只交正面：单面复印件

目的：有的业务只要人像面。
执行方：自动（s02）。需求点：§3-2、§6-2、§10-6。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 只做正面（选 M1、确认），反面不动 | 反面区写「可只做一面」，徽标「未选图」；导出按钮可点；预览徽标「已生成（只含正面）」 |
| 2 | 填好水印后导出 PNG，打开 | 正面在上半页，位置与 S1 的正面相同；下半页全白，没有边框、没有占位框 |
| 3 | 点「清除全部」，这次只做反面（M2），导出 PDF | 反面在下半页，位置与 S1 的反面相同；上半页全白 |

### S3 复印机效果：黑白复印件

目的：用户要像复印机那样的黑白件。
执行方：自动（s03）。需求点：§3-4、§6-7、§6-8。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 打开页面，看 4 版面预览 | 预览下方有「导出颜色」，两个选项「灰度」「彩色」，默认选中「彩色」；5 导出区里没有颜色选项 |
| 2 | 做好双面，选「灰度」 | 预览立即变成黑白，水印也是灰的 |
| 3 | 导出 PNG 和 PDF，打开 | 两个文件都是黑白的，和预览看起来一样 |
| 4 | 改回「彩色」，再导出一次 | 预览恢复彩色；新导出的文件是彩色的 |
| 5 | 在「灰度」「彩色」之间来回点几次 | 任何时候只有一个选项被选中，预览跟着切换 |

### S4 照片横着拍：旋转后再裁剪

目的：照片方向不对，用户自己转正。
执行方：自动（s04）。需求点：§4-3、§4-5、§4-7、§5-2。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 在正面选 M3 | 裁剪区里的照片是横着的；固定提示「歪的照片建议重拍或换一张正的图。」可见 |
| 2 | 连点「旋转 90°」 | 每点一次照片顺时针转 90°，裁剪框回到最大并居中；点四次回到原样；页面上没有任意角度的调节 |
| 3 | 转正后调框、确认、导出 | 导出的卡片方向正确 |
| 4 | 用一张略歪（转了约 5°）的照片走完流程 | 页面不强制重拍，不自动纠斜，能正常确认和导出；卡片按用户画的框原样裁出，不做透视矫正 |
| 5 | 用手机竖拍的原图（相册里显示方向正确）选图 | 裁剪区里照片方向与相册一致；若不一致，用「旋转 90°」能转正 |

### S5 照片太小：画质不足但仍能用

目的：用户只有一张小图，要知道打印可能发糊，但不被拦住。
执行方：自动（s05）。需求点：§4-6、§5-4。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 在正面选 M4，直接确认 | 正面区出现橙色警告，写明「画质不足：所选区域只有 N 像素高，低于输出所需的 638 像素，已放大，打印可能发糊。仍可继续导出。」；徽标「已确认，画质不足」 |
| 2 | 导出 PDF | 导出成功，卡片尺寸与 S1 相同，只是画面较糊 |
| 3 | 用大图 M1 但把框缩到很小再确认 | 同样出现画质不足警告 |
| 4 | 正面重新选 M1，用最大框确认 | 警告消失，徽标「已确认」 |

### S6 选错文件：给出明白的提示

目的：用户选了浏览器读不了的文件，要知道发生了什么、怎么办。
执行方：第 1 至 3 步自动（s06）；第 4 步真机。需求点：§5-3。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 先做好正面，再在正面选 M7 | 正面区出现红框「无法读取这张图片。请换一张 JPG 或 PNG 图。」；原来已确认的正面仍在，预览不变 |
| 2 | 在电脑 Chrome 上选 M6 | 红框提示「这张图是 HEIC 格式，当前浏览器无法读取。请在手机相册里用兼容格式（JPG）导出，或换一张 JPG、PNG 图。」 |
| 3 | 再选 M1 | 错误提示消失，正常进入裁剪 |
| 4 | 真机 iOS Safari 从相册选一张 HEIC 照片 | 要么自动转换后正常裁剪，要么出现第 2 步的 HEIC 提示；不会无反应或卡住。实际表现记入测试记录 |

### S7 水印没填完：导出被拦下

目的：防止导出带空白水印的复印件。
执行方：自动（s07）。需求点：§7-4、§7-5。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 做好正面，水印选模板「仅供____办理业务使用，他用无效 日期」，用途空着 | 导出按钮不可点，旁边写「请填写用途」；水印徽标「已开启，待填写：请填写用途」；预览下方写「水印待填写，预览暂不含水印」，预览上没有水印 |
| 2 | 用途填「开户」 | 导出按钮可点；预览出现「仅供开户办理业务使用，他用无效 日期」的水印 |
| 3 | 用途输入超过 10 个字 | 第 11 个字起输入不进去 |
| 4 | 把日期清空 | 导出被拦，原因「请选择水印日期」 |
| 5 | 把日期改成 2026-01-05 | 水印里的日期变成「2026年1月5日」；导出文件名仍用导出当天的日期 |
| 6 | 两面都不做，看导出区 | 导出按钮不可点，原因「请先确认至少一面」 |

### S8 自定义水印文字

目的：预设模板不合用时，用户自己写。
执行方：自动（s08）；水印逐字内容由页面徽标文字核对，导出画面上核对的是有水印、灰色、斜排、多行，逐字比对画面需桌面目视。需求点：§7-5。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 选「自定义」，文字框空着 | 导出被拦，原因「请填写水印文字」 |
| 2 | 输入「仅限本人办理社保使用」 | 预览和导出文件里的水印就是这句话，不自动加日期 |
| 3 | 输入 24 个字的长句 | 水印字号自动变小，整句在卡片上仍能看全或成行重复；超过 24 字输入不进去 |

### S9 给自己存档：关闭水印

目的：自己存底不需要水印，但关闭时要被提醒一次。
执行方：自动（s09）。需求点：§7-1、§10-5。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 打开页面 | 「添加水印」默认勾选 |
| 2 | 取消勾选 | 弹出一次确认框「关闭水印后，导出的复印件上将没有任何防挪用文字。确定关闭吗？」 |
| 3 | 在确认框点取消 | 水印保持开启，预览水印还在 |
| 4 | 再取消勾选，这次点确定 | 水印徽标「已关闭」；预览上没有水印；只弹了这一次框 |
| 5 | 导出 PDF 和 PNG | 两个文件里都没有任何水印文字 |
| 6 | 重新勾选 | 不弹框，水印恢复 |

### S10 用完清除

目的：用户在别人的电脑上用完，要确认什么都没留下。
执行方：自动（s10）；第 3 步由脚本在徽标变成「解码中…」的同一刻点清除，代替人手抢点。需求点：§3-5、§8-4、§10-7。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 双面做完、导出颜色选「灰度」、水印填好，点「清除全部」 | 不弹确认，立即清空：预览回到「尚未确认任何一面」，看不到任何照片或卡片；正反面徽标「未选图」；导出颜色回到「彩色」；水印回到默认（开启、模板 1、用途空、日期今天） |
| 2 | 在正面裁剪中途点「清除全部」 | 裁剪区消失，页面上没有照片 |
| 3 | 刚选完一张大图、还在读取时立刻点「清除全部」 | 页面保持清空，过一会儿也不会冒出那张图 |
| 4 | 清除后再选同一张图 | 能正常再次选中并进入裁剪 |

### S11 断网使用

目的：确认整个流程不需要网络，页面也不往外发任何东西。
执行方：第 1 至 3 步自动（s11，用浏览器离线模式代替拔网线）；第 4 步真机。需求点：§1-3、§2-1、§2-2、§8-1、§8-5、§10-1、§10-2。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 关掉电脑的 Wi-Fi 和网线，双击 `index.html` | 页面正常打开，样式完整 |
| 2 | 打开浏览器开发者工具的「网络」面板，刷新页面 | 除页面文件本身外，没有任何请求 |
| 3 | 断网状态下走完 S1 全流程，再点一次「清除全部」 | 每一步都正常，PDF、PNG 都能导出；网络面板始终没有新请求 |
| 4 | 真机：手机开飞行模式，打开网站版页面 | 观察能否打开；能打开就走一遍流程。结果只记录，不作通过条件 |

### S12 手机上拍照做复印件

目的：用户在手机上直接拍证件生成复印件。
执行方：真机，iOS Safari 与 Android Chrome 各做一遍。需求点：§1-1、§1-2、§2-3、§4-4、§10-8。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 用手机浏览器打开网站版页面 | 单列排布，按钮够大好点，没有横向滚动条 |
| 2 | 在正面点「选图」 | 弹出系统的选择菜单，里面有「拍照」和「照片图库」；页面本身不直接打开相机 |
| 3 | 选「拍照」，拍正面，用照片 | 进入裁剪，照片方向正确 |
| 4 | 用手指拖角点 | 手指上方出现放大镜，能看清角点附近；松手后放大镜消失 |
| 5 | 用手指拖框内 | 框跟着移动；手指放在裁剪区以外时页面能正常上下滚动 |
| 6 | 反面从相册选图，完成双面；填水印，导出 PDF | 文件能保存或打开，内容与 S1 第 9 步一致 |
| 7 | 点输入框填用途 | 页面不会被自动放大 |

### S13 大照片不崩溃

目的：手机原图很大，页面不能卡死或崩溃。
执行方：第 1、2 步自动（s13）；第 3 步真机。需求点：§5-1、§10-9。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 正反面都选 M5 的 12MP 照片，确认，导出 PDF 和 PNG | 全程不崩溃、不白屏；导出文件正常 |
| 2 | 选长边超过 4000 的大图 | 能正常进入裁剪，裁剪操作不卡顿 |
| 3 | 真机上用手机原相机拍的照片走完双面导出 | 浏览器不崩溃、不自动刷新页面 |

### S14 隐私核对

目的：确认导出文件里没有拍摄信息，页面也不记住用户填过的东西。
执行方：自动（s14）；第 2、3 步在访达与 PDF 阅读器里查看信息由脚本读文件内容代替。需求点：§7-6、§8-2、§8-3、§10-4。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 用 M8 做正面，导出 PNG 和 PDF | 导出成功 |
| 2 | 在访达里对 PNG 点「显示简介」，或用预览程序的「显示检查器」查看 | 没有拍摄地点、相机型号、拍摄时间等信息；PNG 图像尺寸为 2480×3508 像素 |
| 3 | 查看 PDF 的文档属性 | 没有作者、生成程序等信息；页面尺寸为 210×297mm（A4） |
| 4 | 水印填好用途后刷新页面 | 用途清空、模板回到默认、日期为今天；照片和预览也都没了 |
| 5 | 关掉浏览器再打开页面 | 同样什么都没保留 |
| 6 | 检查文件名 | 只含「身份证复印件_」加日期，不含姓名或证件号 |

### S15 浏览器兼容与过旧提示

目的：确认在支持范围内的浏览器都能用，过旧浏览器有提示。
执行方：Chrome 自动（第 1 步由 s01 覆盖，过旧提示不出现由 s15 检查）；Edge、Safari 与第 2 步旧浏览器为桌面手工；真机见 S12。需求点：§2-4。

| 步 | 用户操作 | 期望结果 |
|---|---|---|
| 1 | 在 Chrome、Edge、Safari 最新版各走一遍 S1 | 三个浏览器结果一致，导出文件名正确 |
| 2 | 在不支持的旧浏览器上打开（有条件时做） | 页面顶部出现「此浏览器版本过旧，可能无法正常使用，建议升级后再试」，仍可尝试使用 |

## 3. 反向检查：v1 明确不做的事

对照需求 §9，以下在走上述场景时顺带确认，页面上都不应出现：
