# id-copy-maker 设计文档（v1）

需求唯一来源：docs/requirements.md。本文只写目标终态。交付物为项目根目录单个 `index.html`，原生 JS，零依赖，无构建。

## 1. 目标与做法

### 1.1 目标

在浏览器里把身份证正反面照片裁剪、加水印、拼到 A4 一页，导出 PDF 或 PNG，全程只在本机内存里完成，不产生任何网络请求。

### 1.2 做法与理由

| 决策 | 理由 |
|---|---|
| 单 HTML，两个内联 script：`pure-core`（纯函数）和 `app`（DOM 与事件） | 满足单文件交付；纯函数区块可被测试脚本按标记截取，在 node 下运行 |
| 图片用 `<img>` 解码后画进"源画布"，不用位图对象 API | `<img>` 路径的 EXIF 纠正行为最成熟，且同一次绘制完成缩到 4000 以内 |
| 旋转只改一个状态值 `rot`，绘制时再做变换 | 不复制 4000 像素大图，省一份内存 |
| 版面、水印、PDF、PNG 元数据全部用纯函数算出 | 数值可在 node 下直接断言，实现者无需靠肉眼核对 |
| 预览与导出共用同一个 `composeSheet`，预览只多一层缩放 | 避免预览与导出两套逻辑漂移 |
| PDF 手工拼装，只嵌一张 JPEG | 需求禁止引入 PDF 库 |
| 页面不使用任何网络、存储、缓存 API，CSP 兜底 | 用户硬约束：纯本地，无后端，无上传 |

### 1.5 三条判定规则

| 编号 | 规则 |
|---|---|
| R1 画质不足 | 裁剪框在源图中覆盖区域的高度（源图像素，按缩到 4000 以内后的源画布计）四舍五入取整后小于输出卡片高 `CARD_H`（638）时触发警告，即发生放大就警告；只警告，不阻止导出。判定细则见 §4.3 `isLowRes` |
| R2 水印门 | 水印开启，且用途文字（模板 1 与自定义）或日期（模板 1、2、3）为空时，两个导出按钮禁用，按钮旁用文字写明原因；不导出带空白占位的水印 |
| R3 关闭提示 | 用户每次把水印从开切到关，弹一次确认框；确认才关闭，取消则保持开启 |

R1 与需求 `docs/requirements.md:36`「短边不足 600 像素」的关系：源画布短边 s 小于 638 时，任何朝向、任何大小的裁剪框高都不超过 s。推导：`maxBox` 的框宽不超过旋转图宽 `rw`，框高 = 框宽 × 54 / 85.6 且不超过旋转图高 `rh`；54 / 85.6 小于 1，故框高也小于 `rw`；所以框高不超过 `min(rw, rh)`，即 s。s 为整数且不大于 637，取整后的框高不大于 637，必触发警告。原图短边不足 600 时，缩到 4000 以内后的源画布短边只会更小或相等，同样必触发，需求 :36 的条件被 R1 覆盖。

## 2. 总体结构

### 2.1 文件布局

`index.html` 自上而下：`<meta charset>`、`viewport`、CSP meta、`<style>`、页面骨架（五个步骤区块，直接放在一个两栏容器内，见 §10.1）、`<script id="pure-core">`、`<script id="app">`。

`pure-core` 里只有纯函数与常量，顶层不碰 `window`、`document`、`navigator`，最后一句形如 `const IDCopyPure = Object.freeze({...})`，导出表供测试截取。`pure-core` 与 `app` 是同一页面的两个 `<script>`，共用同一全局作用域：`app` 直接使用 `pure-core` 的顶层名（如 `composeSheet`、`buildPdf`、`formatYmd`），不经 `IDCopyPure` 取用。

`app` 区块的 `state` 与导出等处理函数为 script 顶层声明（`const`、`function`），不包 IIFE，页内脚本可只读 `state`。验收经 DOM 操作触发处理函数，不直接调用处理函数，也不加测试钩子（§15）。

### 2.3 状态模型

`app` 里只有一个 `state` 对象，界面全部由 `render()` 从它推导。

| 字段 | 类型 | 说明 |
|---|---|---|
| `epoch` | 整数 | 每次"清除全部"加 1；异步回调开头比对，不一致则丢弃结果 |
| `sides.front` / `sides.back` | `Side` | 两面各一份 |
| `Side.card` | 画布或 null | 已确认的卡片图，尺寸为卡片常量 |
| `Side.lowRes` | 布尔 | 已确认卡片是否触发 R1 |
| `Side.loading` | 布尔 | 正在解码 |
| `Side.cropper` | 对象或 null | 裁剪中的状态，见 §4.2 |
| `Side.message` | `{kind, text}` 或 null | 该面步骤区的错误或警告，kind 取 `error` 或 `warn` |
| `wm.on` | 布尔 | 默认 true |
| `wm.tpl` | `t1`、`t2`、`t3`、`custom` | 默认 `t1` |
| `wm.purpose` | 字符串 | 模板 1 的用途 |
| `wm.custom` | 字符串 | 自定义整句 |
| `wm.date` | `YYYY-MM-DD` 字符串 | 默认本地今天，可改 |
| `exportColor` | `color` 或 `gray` | 默认 `color`；预览与导出共用的唯一颜色来源，"灰度"对应复印机效果，"彩色"对应原件彩色效果 |
| `busy` | 布尔 | 导出进行中 |
| `exportMsg` | `{kind, text}` 或 null | 导出区的结果或错误 |

### 2.4 数据流

1. 选图：文件 → 解码 → 源画布（长边不超 4000）→ `Side.cropper`。
2. 确认裁剪：源画布按框区域画进卡片画布 → `Side.card`；源画布立即释放；`Side.cropper` 置空。
3. 预览：`state` → `composeSheet` 画进缩放预览画布 → `exportColor` 为灰度时在这张小画布上转灰；水印、卡片、开关、导出颜色任一变化都重画。
4. 导出：创建整页大画布 → `composeSheet` → `exportColor` 为灰度时转灰 → PNG 或 JPEG → 字节拼装 → 下载 → 立即释放大画布。
5. 清除：`epoch` 加 1，释放全部画布、地址、表单，重置 `state`，`render()`。

## 3. 数值表

### 3.1 版面（像素，300 DPI）

| 项 | 值 | 算式 |
|---|---|---|
| 页面宽 `PAGE_W` | 2480 | 需求固定 |
| 页面高 `PAGE_H` | 3508 | 需求固定 |
| 卡片宽 `CARD_W` | 1011 | 85.6 mm 按 300 DPI |
| 卡片高 `CARD_H` | 638 | 54 mm 按 300 DPI |
| 间距 `GAP` | 354 | 30 mm 按 300 DPI 取整 |
| 卡片左上角 x（两张相同） | 734 | `floor((PAGE_W - CARD_W) / 2)` |
| 双卡总高 | 1630 | `2 * CARD_H + GAP` |
| 正面左上角 y | 939 | `floor((PAGE_H - 1630) / 2)` |
| 反面左上角 y | 1931 | `939 + CARD_H + GAP` |
| 正面占据 y 范围 | 939 至 1577 | 全部位于上半页（y 小于 1754） |
| 反面占据 y 范围 | 1931 至 2569 | 全部位于下半页（y 不小于 1754） |
| 页面中线 | 1754 | 恰为两卡间隙的中心 |
| 边框线宽 `BORDER` | 4 | 0.3 mm 约 3.54 px，取 4；沿卡片内侧描边 |

边框画法：`strokeRect(x + 2, y + 2, CARD_W - 4, CARD_H - 4)`，线宽 4，使描边完全落在卡片矩形内，卡片外尺寸保持 1011×638。

水平方向的 734 由 `floor` 取整，偏左 1 像素：左边距 734，右边距 `2480 - 734 - 1011 = 735`；上边距 939，下边距 `3508 - 2569 = 939`。

只选一面时坐标不变，另一半不画任何东西（不画边框，不画占位）。

## 4. 图像加载与裁剪

### 4.1 选图与解码

| 步 | 动作 |
|---|---|
| 1 | `<input type="file" accept="image/*">`，不写 `capture` 属性；手机上由系统选择器提供"拍照"和"相册" |
| 2 | change 事件取 `files[0]`，立刻把 `input.value` 置空（同一文件可再选），记下当前 `epoch` |
| 3 | 同一时刻只允许一个裁剪器：另一面正在裁剪时，本面"选图"按钮禁用，旁边写"请先确认或取消当前裁剪" |
| 3a | 本面自己正在裁剪时（`Side.cropper` 非空）再选图：本面"选图"按钮同样禁用，旁边写同一句提示，不替换、不静默忽略。取禁用而不取"先取消旧裁剪器再解码"：避免用户未点取消就丢掉正在调整的裁剪框，也避免新旧两份源画布同时存在（§12），与步 3 的另一面规则同构 |
| 4 | `URL.createObjectURL(file)` 得地址并登记进 `state.urls`；`new Image()` 设 `src`；等 `onload` |
| 5 | onload 里先比对 `epoch`，已变则撤销地址并退出；否则取 `naturalWidth`、`naturalHeight` 为 w、h，`scaleToMax(w, h, MAX_EDGE)` 得 sw、sh |
| 6 | 建源画布 sw×sh，`imageSmoothingQuality='high'`，`drawImage(img, 0, 0, sw, sh)`；随即撤销地址并丢弃 img 引用。不对 `img` 的 `src` 赋空串：空地址在个别浏览器上是否触发请求没有一手来源，该写法会让 §15 第 2 条的"请求数为 0"依赖未核实的行为 |
| 7 | 建 `Side.cropper`：`rot=0`，`box=maxBox(sw, sh)`，进入裁剪状态 |

EXIF 方向：不给 `<img>` 设任何 `image-orientation` 样式，沿用浏览器默认值 `from-image`（一手原文见 §1.4），期望 `naturalWidth`、`naturalHeight` 与 `drawImage` 都已是纠正后的朝向。

备用路径：若实测发现 `drawImage` 未按 EXIF 纠正，把步 4 至 6 换成 `createImageBitmap(file, { imageOrientation: 'from-image' })` 再画进源画布，其余不变。两种行为在 iOS Safari 16、Android Chrome 上是否如此，待实测（§16 T2）。

解码失败（`onerror`，或 w、h 为 0）的处理：

| 条件 | 提示文字（写入该面 `message`，kind=error） |
|---|---|
| `file.type` 为 `image/heic`、`image/heif`，或文件名后缀为 `.heic`、`.heif` | 这张图是 HEIC 格式，当前浏览器无法读取。请在手机相册里用兼容格式（JPG）导出，或换一张 JPG、PNG 图。 |
| 其它失败 | 无法读取这张图片。请换一张 JPG 或 PNG 图。 |

失败后该面保持失败前的状态：已确认的卡片不丢，也不进入裁剪。

### 4.2 裁剪状态

`Side.cropper` 的字段：

| 字段 | 说明 |
|---|---|
| `src` | 源画布，长边不超过 4000 |
| `rot` | 0、90、180、270，顺时针；旋转只改此值，不复制画布 |
| `rw`、`rh` | 旋转后图的宽高：`rot` 为 0、180 时等于 `src` 宽高，为 90、270 时对调 |
| `box` | `{x, y, w}`，单位为旋转后图的像素；高由 `h = w * 54 / 85.6` 推出 |
| `drag` | 空，或 `{pointerId, mode:'move'|'corner', corner, startBox, startPt}` |
| `view` | 视图画布及其显示缩放；`rect.width / rw` 即显示比例 |
| `mag` | 放大镜是否显示及其位置 |

状态迁移：

| 从 | 事件 | 到 |
|---|---|---|
| 空闲 | pointerdown 命中角点 | 缩放中 |
| 空闲 | pointerdown 命中框内 | 平移中 |
| 空闲 | pointerdown 未命中 | 空闲（不处理） |
| 平移中、缩放中 | pointermove | 同状态，更新 `box` |
| 平移中、缩放中 | pointerup、pointercancel | 空闲 |
| 空闲 | 点"旋转 90°" | 空闲，`rot` 加 90 取模 360，`box` 重置为 `maxBox(rw, rh)` |
| 空闲 | 点"确认裁剪" | 裁剪器释放，该面得到 `card` |
| 空闲 | 点"取消" | 裁剪器释放，该面保持进入裁剪前的状态 |

### 4.3 裁剪几何（纯函数）

| 函数 | 规则 |
|---|---|
| `scaleToMax(w, h, max)` | 长边不超过 max 时原样返回，否则按比例缩小，宽高取整，返回 `{w, h, scale}` |
| `maxBox(rw, rh)` | `w = min(rw, rh * 85.6 / 54)`，`x = (rw - w) / 2`，`y = (rh - w * 54 / 85.6) / 2` |
| `moveBox(box, dx, dy, rw, rh)` | `x` 夹在 `[0, rw - w]`，`y` 夹在 `[0, rh - h]` |
| `resizeBox(box, corner, px, py, rw, rh, minW)` | 对角点为锚点；`dx`、`dy` 为指针相对锚点朝外方向的距离；`w = max(dx, dy * 85.6 / 54)`；再夹在 `[minW, maxW]`，`maxW` 取水平余量与垂直余量乘比例的较小者；`x`、`y` 由锚点和方向推出 |
| `hitTest(box, px, py, tol)` | 先判四个角点（距离不超过 `min(tol, w/3)`），再判框内，返回 `'tl'`、`'tr'`、`'bl'`、`'br'`、`'move'` 或 `null` |
| `isLowRes(box)` | `Math.round(box.h) < CARD_H` 即真（R1）。`box` 只存 `w`，`box.h` 由 `box.w * 54 / 85.6` 现算，单位为源图像素，按缩到 4000 以内之后的源画布计。比较前先四舍五入：最大框恰好对应输出尺寸时，`box.h` 会因浮点误差落在 637.99… 一类的值上，取整后为 638，不误报。取整后的值小于 638 才为真，所以 `box.h` 为 637.4 真（取整 637），637.6 假（取整 638）；恰在取整平局点上结果受浮点影响，不作断言 |
| `rotMatrix(rot, w, h)` | 源图到旋转图的仿射矩阵 `[a,b,c,d,e,f]`：0 度为单位阵；90 度为 `[0,1,-1,0,h,0]`；180 度为 `[-1,0,0,-1,w,h]`；270 度为 `[0,-1,1,0,0,w]` |
| `cropTransform(rot, w, h, box, dw)` | 取 `s = dw / box.w`、`[a,b,c,d,e,f] = rotMatrix(rot, w, h)`，返回 `[a*s, b*s, c*s, d*s, (e-box.x)*s, (f-box.y)*s]`，即源图到卡片画布的矩阵 |

最小框宽 `minW = maxBox(rw, rh).w * 0.25`。

### 4.4 指针交互

- 视图画布设 `touch-action: none`，只用 Pointer Events，鼠标、触摸、笔同一套代码。
- pointerdown：只接受主指针；已有拖动时忽略其它指针；命中后 `setPointerCapture`，记录 `startBox` 与起点（已换算成旋转图坐标）。
- pointermove：按起点差换算 `dx`、`dy`；平移用 `moveBox`，缩放用 `resizeBox`；用 `requestAnimationFrame` 合并重绘。
- 屏幕到旋转图坐标：`(clientX - rect.left) / rect.width * rw`，纵向同理。
- 角点命中半径 `HANDLE_R` 为 CSS 像素，换算成图像素：`HANDLE_R / (rect.width / rw)`；触屏（`pointerType==='touch'`）取 32，其余取 24。
- 视图画布 CSS 宽度不超过容器宽度和 720 像素，内部像素宽度 = CSS 宽度 × `min(devicePixelRatio, 2)`。

### 4.5 放大镜

| 项 | 规则 |
|---|---|
| 出现条件 | `drag.mode==='corner'` 且 `pointerType==='touch'` |
| 位置 | 圆心在手指正上方 `MAG_LIFT` 处，直径 `MAG_SIZE`；上方放不下时放到手指正下方；横向夹在裁剪区域内 |
| 内容 | 从视图画布取以当前角点为中心、边长 `MAG_SIZE / MAG_ZOOM` 的方块，放大画进独立的小画布，中心画十字线；小画布用 CSS 圆角成圆形 |
| 消失 | pointerup、pointercancel、确认、取消、清除 |

### 4.6 旋转、确认与输出

- 旋转作用在源图上：每次点击 `rot` 加 90，视图按 `rotMatrix` 重绘，不复制画布。
- 确认：新建 `CARD_W×CARD_H` 画布，先涂白，再设 `cropTransform(rot, src.width, src.height, box, CARD_W)` 为变换矩阵，`drawImage(src, 0, 0)`。小图在此被放大。
- 确认后 `Side.lowRes = isLowRes(box)`，随即释放源画布（宽高置 0）和视图画布，`cropper` 置空。
- 画质不足时 `message` 为 warn：画质不足：所选区域只有 N 像素高，低于输出所需的 638 像素，已放大，打印可能发糊。仍可继续导出。N 取 `Math.round(box.h)`，与 `isLowRes` 用同一个取整值，所以 N 恒不大于 637。

### 4.7 固定提示

裁剪区域内始终显示一行固定文字：歪的照片建议重拍或换一张正的图。不做自动歪斜检测，不阻止继续。

## 6. 版面合成与预览

### 6.1 composeSheet

`composeSheet(ctx, {k, front, back, wmText})`，`ctx` 为任意 2D 上下文（便于测试时传记录用的假上下文）。

1. `save`；`scale(k, k)`；整页涂白 `(0, 0, 2480, 3508)`；`imageSmoothingQuality='high'`。
2. 对存在的面（先正后反）：`drawImage(card, 734, y)`，y 取 939 或 1931；`wmText` 非空则 `drawWatermark`；最后 `strokeRect(x+2, y+2, 1007, 634)`，线宽 4，颜色 `#000`。
3. `restore`。

导出取 `k=1`，预览取 `k=PREVIEW_W/2480`。没选的那一面完全不画（不画边框，不画占位）。坐标数值的唯一来源是 §3.1，实现里由 `computeLayout()` 给出，不在别处重写。

### 6.2 预览

| 项 | 规则 |
|---|---|
| 画布 | 内部 900×1273 不变，`PREVIEW_W` 与预览、导出的缩放关系不变。CSS 宽度 = 模块 4 内容宽 + 12 像素，铺满模块 4，纸边到模块 4 边框内侧的左右距离各 8 像素，宽高比保持 900:1273。宽屏、窄屏同一规则，不设最大宽，不设高度上限。取 8 的理由：用户要求纸边与模块边缘只留"一个字母宽"的缝，页面字号 16 像素，一个拉丁字母宽约 8 至 9 像素。实现方式（纯 CSS）见 §10.3「预览画布缝宽」 |
| 预览尺寸 | 画布宽 = 所在容器内容宽 + 12，高 = 宽 × 1273/900（计入 1 像素边框的误差小于 1%）。右栏内容宽 = 右栏宽 − 30（分区内边距 28 加边框 2，§10.1）；窄屏单列内容宽 = min(视口宽, 760) − 32 − 30。1280×800：内容宽 633 − 30 = 603，画布宽 603 + 12 = 615，高 615 × 1273/900 ≈ 870，面积约 535,000，为上一轮读数 396×560（221,760）的 2.41 倍，为参照面积 163,152 的 3.28 倍。1024×768：内容宽 589 − 30 = 559，画布宽 571，高 ≈ 808，面积约 461,200，为上一轮 380×538（204,440）的 2.26 倍，为同视口参照画布 326.4×460.8（面积 150,405）的 3.07 倍。800×800：内容宽 min(800, 760) − 32 − 30 = 698，画布宽 710，高 ≈ 1004，面积约 713,000，为上一轮 420×594（249,480）的 2.86 倍。三者都不小于参照面积的 4/3。画布尺寸只由容器宽决定，与视口高度无关。取舍：画布高于右栏可视高度（宽屏 800 高的视口里右栏可用高度 768），看全 A4 下半部分要在右栏内向下滚动，右栏自身纵向滚动保证预览下半部分可达；导出区在左栏，导出按钮随页面滚动可达，不依赖右栏滚动（§10.1） |
| 重画时机 | 卡片、水印设置、开关、导出颜色任一变化；用 `requestAnimationFrame` 合并 |
| 水印 | 校验通过才画；水印开启但未填完时预览不含水印，并在预览下方写"水印待填写，预览暂不含水印" |
| 预览颜色 | 预览随 `exportColor` 显示：选彩色，预览为原件彩色；选灰度，预览为黑白复印效果。灰度做法：`composeSheet` 画完后，对这张 900×1273 预览画布调用与导出同一个 `grayscaleCanvas`（同一 `BAND_ROWS` 分段、同一 `grayBand` 公式，§7.2），所以预览灰度值与导出灰度值逐像素同一公式，不会出现预览与导出不一致。理由：预览的目的是让用户看到导出的样子；若用 CSS 滤镜加对比度，预览比导出更黑，用户看到的与拿到的不同。转灰只作用于小画布（约 4.6 MB），不读导出大画布，§12 的内存策略不变。每次重画都先彩色合成再转灰，切回彩色即恢复，不保留灰度副本 |
| 导出颜色选项 | 位于 4 预览区块内、预览画布正下方，布局与文字见 §10.3；两面都没有卡片时选项仍可选，选择只写入 `exportColor`，预览保持空状态 |
| 空状态 | 两面都没有卡片时，预览画布不显示，改显示"尚未确认任何一面" |

## 7. 导出

### 7.1 流程

| 步 | 动作 |
|---|---|
| 1 | 处理函数开头调 `exportGate`，不通过则显示原因并结束 |
| 2 | `busy=true`，记下 `epoch`，禁用两个导出按钮和清除以外的输入 |
| 3 | 新建 2480×3508 画布；取不到 2D 上下文则报错"导出失败：浏览器无法创建画布，可能内存不足。请点"清除全部"后重试"，不做降级 |
| 4 | `composeSheet(ctx, {k:1, ...})` |
| 5 | 选灰度时，按 `BAND_ROWS` 行一段：`getImageData`、`grayBand`、`putImageData`，逐段处理，不一次取整页 |
| 6 | PNG：`toBlob('image/png')`；PDF：`toBlob('image/jpeg', 0.92)`。回调里先把大画布宽高置 0，再处理字节 |
| 7 | `toBlob` 给出空值则报错"导出失败：浏览器没有生成文件，请重试"；比对 `epoch`，已变则丢弃 |
| 8 | PNG：读出字节，`injectPngPhys` 写入 300 DPI；PDF：`jpegInfo` 取宽高与分量数，`buildPdf` 拼装 |
| 9 | 建 Blob，`createObjectURL`（登记进 `state.urls`），临时 `<a download>` 点击，60 秒后撤销地址 |
| 10 | `busy=false`，导出区显示"已导出：文件名" |

### 7.2 灰度

- 彩色：不处理。
- 灰度：在画布像素上转灰后再编码。`grayBand(data)` 对每个像素取 `g = (77*R + 150*G + 29*B) >> 8`，写回 R、G、B，A 不动。
- 颜色来源只有 `state.exportColor`（§2.3）。预览画布（§6.2）与导出大画布调用同一个 `grayscaleCanvas`，转灰公式只此一份。
- 浏览器编码出的 JPEG 通常仍是 3 个分量；PDF 的颜色空间以 `jpegInfo` 读到的分量数为准（见 §8），不假设。

### 7.3 PNG 元数据

- 画布编码本身不含 EXIF、GPS。`injectPngPhys` 在 `IHDR` 之后插入 `pHYs` 块：X、Y 各 11811（每米像素数），单位字节 1；已有 `pHYs` 则不重复插入。
- `listPngChunks(bytes)` 列出各块类型，供验收脚本检查不含 `eXIf`、`tEXt`、`iTXt`、`zTXt`。`crc32` 为块校验所用。

### 7.4 文件名

`exportFileName(date, ext)` → `身份证复印件_` + `formatYmd(date)` + `.` + ext，例如 `身份证复印件_20261025.pdf`。日期取导出当天的本地日期，不含姓名与证件号。

## 8. PDF 拼装

### 8.1 对象结构

| 对象 | 内容 |
|---|---|
| 文件头 | `%PDF-1.4` 加一行含高位字节的注释 |
| 1 0 | `<< /Type /Catalog /Pages 2 0 R >>` |
| 2 0 | `<< /Type /Pages /Kids [3 0 R] /Count 1 >>` |
| 3 0 | `<< /Type /Page /Parent 2 0 R /MediaBox [0 0 595.28 841.89] /Resources << /XObject << /Im0 4 0 R >> >> /Contents 5 0 R >>` |
| 4 0 | 图像流：`/Type /XObject /Subtype /Image /Width W /Height H /ColorSpace CS /BitsPerComponent 8 /Filter /DCTDecode /Length N`，流内容为 JPEG 原字节 |
| 5 0 | 内容流：`q 595.28 0 0 841.89 0 0 cm /Im0 Do Q`，`/Length` 为该字符串字节数 |
| xref | 6 条：第 0 条为 `0000000000 65535 f`，后 5 条为各对象偏移 |
| trailer | `<< /Size 6 /Root 1 0 R >>`，不写 `/Info`，不带任何作者、生成器信息 |

`CS`：`jpegInfo` 读到 3 个分量写 `/DeviceRGB`，1 个写 `/DeviceGray`，其它（含 4 分量）报错"导出失败：不支持的图像颜色格式"，不转换。

### 8.2 偏移计算

- 所有部分先转成字节数组，依次追加到一个累计长度计数器；每个对象开始前记录当前累计长度为该对象偏移。
- xref 每条恰好 20 字节：10 位补零偏移、空格、5 位代数、空格、`n` 或 `f`、空格、换行。
- `startxref` 后写 xref 表起点的偏移，最后一行 `%%EOF`。
- 字符串转字节用逐字符 `charCodeAt & 0xFF`，不依赖文本编码接口。

### 8.3 jpegInfo 与元数据

- `jpegInfo(bytes)`：从 `FFD8` 起逐段读标记，遇 SOF 标记（`FFC0` 至 `FFCF`，排除 `FFC4`、`FFC8`、`FFCC`）读高、宽、分量数；找不到返回 `null`，导出报错"导出失败：生成的图像无法解析"。
- 导出前断言宽 2480、高 3508，不符则报错，不导出。
- `jpegHasExif(bytes)`：扫描 `FFE1` 段是否以 `Exif` 开头，供验收脚本使用。

## 10. 界面与步骤状态

### 10.1 页面骨架

页面由标题、隐私说明、过旧警告条和"两栏容器"自上而下组成。两栏容器直接包五个 `<section>`。DOM 里五个 `<section>` 始终依次为 1 正面、2 反面、3 水印、4 预览、5 导出与清除。窄屏的显示顺序、读屏顺序和键盘 Tab 顺序都靠这个先后；宽屏把 5 放进左栏靠 CSS 网格定位，不靠挪动 `<section>`，所以排布只用 CSS，不用脚本。

每段标题行含序号、名称和状态徽标；状态徽标所在元素 `role="status"`、`aria-live="polite"`。

两种布局的取值：

| 项 | 宽屏 | 窄屏 |
|---|---|---|
| 适用视口宽度 | 不小于 1024 CSS 像素 | 小于 1024 CSS 像素 |
| 页面最大宽度 | 1200 CSS 像素，居中，页面左右内边距各 16 | 760 CSS 像素，居中，页面左右内边距各 16 |
| 分栏 | 两栏并排，栏间距 16。左栏宽取比例值：（两栏容器宽 − 476）× 3/4，其中 476 = 栏间距 16 + 基准右栏宽 460，（容器宽 − 476）为基准左栏宽；右栏取余下宽度。页面 1200 时容器宽 1168，基准左栏宽 692，左栏约 519，右栏约 633；视口 1024 时容器宽 992，基准左栏宽 516，左栏约 387，右栏约 589 | 单列，1 至 5 自上而下 |
| 左栏内容 | 1 正面、2 反面、3 水印、5 导出与清除，自上而下依次排列，5 紧接在 3 之下 | 同单列 |
| 右栏内容 | 只有 4 预览区块：预览画布，其下紧随"导出颜色"选项（属 4 预览区块） | 同单列 |

末尾 `1fr` 行的作用：4 跨行，若它比 1、2、3、5 的高度之和还高，多出的高度由 `1fr` 行承接，左栏各 `auto` 行不被撑开，5 与 3 之间没有空隙；4 较矮时该行高度为 0。这条行为由 §15 布局行的"5 的 `top` 减 3 的 `bottom`"读数验证，读数不符则上呈，不自行改做法。窄屏不设网格，五个区块按 DOM 先后单列堆叠。

## 11. 隐私与 CSP

### 11.1 CSP 起点串（待浏览器实测）

写在 `<head>` 最前的 `<meta http-equiv="Content-Security-Policy" content="...">`，一行：

```text
default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src blob: data:; connect-src 'none'; font-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none'; worker-src 'none'; manifest-src 'none'; base-uri 'none'; form-action 'none'
```

| 指令 | 理由 |
|---|---|
| `default-src 'none'` | 未列出的资源类型一律禁止 |
| `script-src 'unsafe-inline'`、`style-src 'unsafe-inline'` | 内联脚本与样式必须可用，不带 `'self'`，因此 file:// 打开时不依赖来源匹配 |
| `img-src blob: data:` | 选图的对象地址是 blob:，放大镜与图标用 data: |
| `connect-src 'none'` | 需求 §8 第 1 条；同时封死网络请求、WebSocket、信标 |
| `form-action 'none'`、`base-uri 'none'` | 页面没有表单提交，也不允许改基准地址 |

元素 `<link rel="icon" href="data:,">` 放在 head 里，使网站版浏览器不再请求 favicon，网络面板请求数才能为 0。

meta 形式的 CSP 不支持 `frame-ancestors`，不写。以上写法在 file:// 下是否满足"内联可用、blob 图可显示、对象地址下载可用、请求为 0"，待浏览器实测（§16 T1）；部署后的表现部署时另行实测。

### 11.2 禁用清单

页面代码（含注释）不得出现下列任何一项，验收时用 §15 的 grep 检查：

| 类别 | 禁用项 |
|---|---|
| 网络 | `fetch`、`XMLHttpRequest`、`WebSocket`、`EventSource`、`sendBeacon`、`<form`、`<iframe`、`<script src`、`<link href`（除 data: 图标）、任何 `http://` 或 `https://` 字符串 |
| 存储 | `localStorage`、`sessionStorage`、`indexedDB`、`caches`、`cookie`、`serviceWorker`、`openDatabase` |
| 其它 | `navigator.mediaDevices`、`getUserMedia`（不调用相机 API）、`window.open`、`navigator.share`、`navigator.clipboard`、`FileSystem` 系列接口 |

图片只经 `URL.createObjectURL` 取得的 blob: 地址和画布在内存中流转；所有地址登记在 `state.urls`，用完即撤销。

## 12. 手机端内存策略

| 阶段 | 做法 | 数量级（RGBA 每像素 4 字节） |
|---|---|---|
| 解码 | 12MP（4000×3000）照片解码一次，立刻缩进长边 ≤4000 的源画布，随后丢弃 `img` 引用 | 约 46 MB（源画布） |
| 裁剪中 | 同一时刻只存在一个裁剪器；视图画布最大 720 CSS 像素宽，内部像素不超过 `720*2` | 视图约几 MB |
| 确认 | 画进 1011×638 卡片画布后，立即把源画布、视图画布宽高置 0 | 卡片约 2.5 MB |
| 预览 | 900×1273 的小画布，不触碰大画布；选灰度时只在这张小画布上转灰 | 约 4.6 MB |
| 导出 | 2480×3508 大画布只在导出时创建一次，编码回调第一行就把宽高置 0；灰度分段处理，不一次取整页 | 约 33 MB |

要点：

- 源图不会与整页大画布同时存在：确认裁剪时释放源图，导出时才建大画布。
- 导出过程中正反面最多同时持有两张卡片（约 5 MB）加一张大画布。
- 创建画布失败或 `toBlob` 返回空时，明确报错并建议"清除全部"，不降级输出低分辨率文件。
- 12MP 手机实测为验收第 9 条，由所有者在真机执行。

### 14.1 纯函数区块截取

`pure-core` 是 `index.html` 里一个带固定 id 的 script，内部不含 `</script>` 字样，不引用 `window`、`document`、`navigator`。测试脚本：

1. 读 `index.html`，用正则 `<script id="pure-core">([\s\S]*?)</script>` 截出代码。
2. 用 node 的 `vm.runInNewContext(code + '\n;IDCopyPure', {})` 在空沙箱里执行，取回 `IDCopyPure`。
3. 空沙箱本身就是"不依赖 DOM"的证明：若纯函数碰了浏览器全局，执行即报错。
4. 沙箱返回的数组和对象来自另一个 realm（执行上下文），与测试脚本里的字面量原型不同：断言前先 `JSON.parse(JSON.stringify(x))`，或逐项比较，不直接对原对象做 `deepStrictEqual`。

产品里的纯函数就是测试用的那份，没有第二份拷贝。

| 导出颜色在哪、选了会怎样 | "导出颜色"紧贴预览画布下方，不用滚到导出区；选灰度预览立刻变黑白，所见即导出结果，选彩色即回到原件彩色；导出区只剩按钮与清除 |
| 需要猜的地方 | 固定提示"歪的照片建议重拍或换一张正的图"，画质不足写明所选区域像素 |

未决偏好（`open`，均待用户确认，默认值照设计走）：

- 自定义水印文字原样使用，不自动追加日期。默认：原样使用（§5.1）。
- 角点缩放的最小框宽取该图最大框宽的 0.25。默认：0.25（`MIN_BOX_RATIO`，§3.3、§4.3）。

### 20.2 边界（本版不做）

## 21. 关键决策

| 决策 | 理由 | 否决的做法 |
|---|---|---|
| 旋转只改 `rot`，导出时才做变换 | 不多占一份大画布 | 每次旋转生成新画布 |
| 画质判据取框高，与输出卡片高 638 比较，放大即警告，不单设 600 阈值 | 需求“图片比它小就放大并警告”与“短边不足 600 像素时给警告”两句都要满足；框高低于 600 必然低于 638，638 已覆盖 600；放大程度取决于裁剪区域（主 agent 裁定） | 按整图短边判断；另设 600 阈值 |
| 导出门同时放在按钮禁用和处理函数 | 禁用可被绕过，业务门必须在入口再守一次 | 只靠禁用按钮 |
| 水印未填完时预览不含水印并提示 | 不展示一个导出不了的样子 | 预览里画占位下划线 |
| 灰度在画布像素上转，不靠 PDF 颜色空间切换 | 需求要求画布转灰后再编码 | 彩色 JPEG 加 PDF 灰度滤镜 |
| 预览颜色跟 `exportColor` 走，预览转灰与导出共用 `grayscaleCanvas` | 需求要求预览随所选颜色显示且与导出一致；同一公式保证预览与导出不一致的情形不存在；只作用于小画布，不读大画布 | 独立的预览切换按钮；CSS 滤镜加对比度做预览（取值与导出灰度不同，预览比导出更黑） |
| "导出颜色"放在预览画布正下方 | 需求写明位于版面预览下方；选了立刻在上方看到结果，不必滚到导出区 | 留在 5 导出与清除区块 |
| 预览铺满模块宽度，缝宽一个字母（8 像素），不设高度上限 | 用户要求：纸边与模块边缘的距离缩短，只留一个字母宽的缝；画布高于右栏可视高度由 4 预览区块自身的纵向滚动承接（§6.2、§10.1）；缝宽用画布左右各 −6 像素外边距实现，其它排布不动（§10.3） | 保留宽度与高度上限；把模块 4 左右内边距改为 8 像素（标题行与选项会一起向两侧移动） |
| 宽屏下 5 导出与清除放左栏，紧接 3 之下；DOM 先后不变，用 CSS 网格显式定位，4 跨行，末行 `1fr` 承接多余高度（§10.1） | 用户要求：预览比右栏可视高度还高，导出区留在右栏要滚动才够得到；保持 DOM 先后 1 至 5，窄屏显示顺序、读屏顺序、Tab 顺序都不用补救；`1fr` 末行避免 4 的多余高度摊给左栏各行造成空隙 | 保持 5 在右栏；把 5 挪到 3 之后、4 之前的 DOM 位置（窄屏会变成 1、2、3、5、4，须再用 `order` 补回视觉顺序，读屏与 Tab 顺序仍错位）；两个分组容器加 `display:contents` 的做法（需在分组之外再套一层，结构比直接网格多，且 `display:contents` 的无障碍表现因浏览器而异，unverified） |
| `pHYs` 写进 PNG | 让 PNG 在打印软件里按 300 DPI 取尺寸 | 不写，靠像素数 |
| 测试靠截取 `pure-core` | 保持单文件交付，同时让纯函数可在 node 下断言 | 在仓库里另存一份纯函数源文件 |
| 不加测试钩子进产品 | 产品代码不为测试带出额外入口 | 暴露导出字节的全局变量 |
