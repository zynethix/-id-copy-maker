# 测试执行与记录

跑测试、留证据、写记录。每次运行都留下能回看的证据，执行记录指向证据，批次记录指向执行记录。

## 何时使用

- 每次改完产品代码：必跑。
- 改完测试脚本或用例集里的自动场景：必跑。
- 批次收口前：必须跑一次全部通过；不通过不收口。

## 运行

- 用项目约定的命令（见项目用例集「执行方」里的自动一行）。
- 长时间运行的输出先写进日志文件（放在工作区外，读完删除），从日志尾部读结论。

## 证据

每次运行都保留：

- 每个用例结束时的截图。
- 每个用例的完整 trace：逐步回放页面、操作、网络请求。
- HTML 报告：汇总全部用例，能点开截图和 trace。

证据按运行分目录存放（目录名带运行时间），不进版本库，只保留最近若干次，更早的自动删除。保留次数、目录位置由项目约定。查看报告用 `npx playwright show-report <报告目录>`。

## 执行记录

项目里有一份要提交的执行记录文件，每次用项目约定的命令完整运行一次，就追加一行（排查时单独重跑某个用例不记在这里，见 `test-triage`）：

`| 时间 | 命令 | 结果（通过数/总数，按用例计数；失败时列出场景编号） | 证据目录 | 触发原因 |`

失败的运行也记，结果写失败的场景编号，再按 `test-triage` 处理。

## 批次记录里写什么

- 自动执行：只写一行指针，指向执行记录里的那一行（时间 + 结果）。
- 手工与真机执行：在当轮批次记录里写一张表 `| 场景/步 | 执行方与浏览器版本 | 结果（通过/不通过/未执行） | 现象 |`；哪些步骤需要手工或真机，看项目用例集。

## 失败时

- 有用例失败，不重跑碰运气，不加自动重试：转 `test-triage`。
- 不改产品代码，也不改脚本，先排查并报告。

## 产出与自查

- 产出：证据目录、执行记录新增一行、批次记录里的指针或手工结果表。
- 自查：这次运行的证据目录存在、报告能打开；执行记录写了；临时日志已删除。
