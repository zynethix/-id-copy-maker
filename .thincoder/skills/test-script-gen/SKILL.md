# 测试脚本生成

把用例集里执行方为「自动」的场景写成脚本，脚本按用户的操作驱动页面，按用户能看到、拿到的结果判定。下面的原则与工具无关；写法一节适用于 Playwright。

## 何时使用

- 用例集新增或修改了自动场景。
- 脚本要跟着产品文案、界面结构的改动更新。
- `test-triage` 判定为脚本缺陷、用户确认后，回到这里修。

用例本身要改时，先用 `test-case-design` 改用例集，再来这里。

## 输入

- 用例集里的自动场景（步骤与期望）。
- 产品代码里的页面结构与文案，用来写定位和断言。只读，不改。

## 原则

1. **只通过用户操作驱动页面**：点按钮、选文件、拖动、填表、处理确认框。不调用页面内部函数，不读写内部状态。
2. **产品里不加测试钩子**：不为测试暴露全局变量、不加测试专用的属性或入口。拿不到的结果换从用户能拿到的地方取（下载的文件、页面文字、画布像素）。
3. **用程序生成假数据**：测试图片、文件在运行时生成，尺寸、方向、元数据按用例的素材要求构造。仓库里不放素材文件，不用真实个人数据。
4. **按用户可见的结果判定**：页面文字照抄产品原文断言；导出文件读字节判断格式、尺寸、元数据，解码像素判断画面。需要「没有某物」时，构造能直接证明没有的素材（例如纯色底），不靠「和另一份不一样」。
5. **绕过界面限制的操作要写明理由**：只在验证「绕过也拦得住」这类防线时用，脚本注释写清。
6. **每个断言对应用例里的一条期望**：断言做不到的期望，在用例里标明由人工确认，不在脚本里假装覆盖。

## 文件与命名

- 脚本文件名以场景编号开头（如 `s01-…`、`s07-s09-…`），文件开头注释写对应的场景和需求点。
- 公共操作（打开页面、生成素材、选图、导出并取文件、解析文件）放进一个辅助模块，场景脚本只写步骤。

## Playwright 写法

- 浏览器：配置里用 `channel` 指定本机浏览器，避免下载自带浏览器（安装依赖需请示）。
- 本地页面：`file://` 地址由 `new URL('<相对路径>', import.meta.url)` 推出，不写死绝对路径。
- 选文件：等 `filechooser` 事件，点「选图」类按钮，`setFiles({ name, mimeType, buffer })` 传内存文件。
- 拖动：`page.mouse.move/down/move(steps)/up`，坐标从画布在屏幕上的位置换算。
- 确认框：`page.once('dialog', d => d.accept() / d.dismiss())`，记下消息原文断言。
- 下载：等 `download` 事件，`download.path()` 读字节，`suggestedFilename()` 断言文件名。
- 读像素：在页面里用 `createImageBitmap` + `OffscreenCanvas` 解码导出字节，取区域像素回传；页面若有 CSP 禁止执行字符串代码，分析放到 Node 侧，页面只回传像素。
- 离线：`context.setOffline(true)`；`file://` 页面本身不受影响，判据写成「除页面文件外无请求、资源计时条目为 0、控制台无报错」。
- 控制台：监听 `console` 的 error 和 `pageerror`，场景末尾断言为空；确需放过的消息逐条写明原因。
- 竞态：要在某个中间状态动作时，用页面里的 `MutationObserver` 在状态出现的同一刻动作并记录，不靠固定等待。
- 证据：配置里 `use.screenshot: 'on'`、`use.trace: 'on'`，`reporter` 加 `['html', { outputFolder, open: 'never' }]` 和 `['json', { outputFile }]`，`outputDir` 指向本次运行的证据目录；目录位置与保留次数由项目约定，保留什么见 `test-run`。
- trace 录制可能在页面上下文里读取 `blob:` 地址；页面 CSP 禁止 `connect-src` 时，控制台会多出对应的拦截消息。这类消息只在确认由 trace 引起后逐条放过，并写明原因。

## 文档与脚本一致

- 先改用例集，再改脚本，同一批完成。
- 改完对照用例逐条核对：每条自动期望都有断言；做不到的已在用例里标为人工。

## 产出与自查

- 产出：脚本与辅助模块（项目约定的测试目录），改动记进当轮批次记录。
- 自查：没有调用页面内部函数；产品代码没改；仓库里没有素材文件；每个脚本开头写了场景编号。
- 之后：用 `test-run` 跑一遍并记录。
